## Проблемы и уязвимости

Общая причина большинства открытых пунктов: ассемблер и эмулятор работают в потоке интерфейса (в браузере —
единственный поток), и у части ресурсов нет предела. Программа ученика, пример из интернета или ссылка
`#code=…&run` может уронить или подвесить вкладку. Поэтому сначала стоит закрыть пункты 14–17.

## Недочёты

- Запасные шрифты для CP437 — только пути macOS (`fonts.rs`); на других системах их нет.
- В вебе эмодзи в тексте пользователя — квадратики (в шрифтах только значки интерфейса).
- В вебе: ☻ ☼ ⌂ ⁿ в окнах с текстом, нет PWA/офлайна, кеш GitHub Pages — 10 минут.
- Веб — холст: экранные чтецы его не видят, текст программы нельзя найти поиском браузера (AccessKit в eframe
  не включён).
- Хранилище браузера — около 5 МБ на всё (программы, диск C:, настройки); нет выгрузки всех программ одним
  архивом и загрузки обратно. IndexedDB / OPFS дали бы больше места.
- UI-тесты сохраняют PNG-снимки, но не сравнивают их с эталонами: визуальную регрессию видно только глазами.
- Сборка, `emulate` и долгие операции идут в потоке интерфейса: даже без бомб (пункт 15) большой файл
  подвешивает кадр. В вебе нужен бюджет времени или Web Worker.
- Карточка *Last step* (что изменила инструкция и почему такие флаги) есть только в интерфейсе планшета;
  у окна эмулятора на десктопе её нет, хотя `Session::last_step` общий.
- Незакрытые пункты плана: 2.8 (`STRUC`, `IRP/IRPC`, `ASSUME`), 3.7 (CGA 4/5/6, VGA 12h), 6.6 (FASM).
- INT 33h — базово; нет INT 21h/4Bh (запуск программ).
- Ассемблер не принимает `ENTER`, `BOUND`, `INS` / `OUTS` (процессор их выполняет) — перепроверено 2026-11-01.
- 8087: трансцендентные функции в f64 (не 64 бита мантиссы); незамаскированные исключения не вызывают прерывание;
  регистры FPU нельзя править в окне и использовать в watch (`st0`); нет сверки вычислений с QEMU (его x87 — точный).
- NASM: нет EXE, `%rotate`/`%0`, `%strlen`/`%substr`, `incbin`, чисел с плавающей точкой, контекстных макросов.
- Интерфейс планшета, PR 4 спецификации V2.2: Output — Screen | Devices | Messages, ряд ASM-клавиш над системной
  клавиатурой, быстрые переходы Memory (CS:IP, DS:SI, SS:SP); README со скриншотами.

## Куда развивать

По порядку: сначала надёжность (без неё ссылки и примеры из интернета опасно открывать), потом то, что
отличает проект как инструмент обучения, потом охват платформ.

1. **Надёжность — пределы и изоляция.** Пункты 14–19: бюджеты на развёртку препроцессора, журнал, вывод,
   историю, диск хоста, глубину выражений; перехват паник с сообщением; фаззинг в CI. Здесь же — общий
   «паспорт ресурсов» `Machine` (сколько памяти занимают история, вывод, журнал), чтобы показывать его в окне
   и тестировать.
2. **Обучение — главное отличие от Emu8086.**
   - *Last step* и «Why did this happen?» в окне эмулятора на десктопе (сейчас только на планшете).
   - Задания с автопроверкой прямо в приложении: формат `;! input / output / screen` уже есть в тестах программ;
     задание — ссылка или файл, кнопка *Check* сравнивает вывод, экран и регистры.
   - Наглядность: счётчик тактов 8086 и тепловая карта исполнения по строкам, диаграмма стека
     (кадры CALL / PUSH), подсветка байтов памяти, которые изменил шаг.
3. **Отладчик:** точки останова на запись/чтение памяти и порта, reverse continue (назад до точки останова —
   история уже есть), регистры FPU в watch.
4. **Редактор:** автодополнение, переход к определению метки/переменной, outline файла, форматирование.
5. **Платформы:** PWA с офлайном; сборки для Linux и Windows в CI (eframe переносим; нужны запасные шрифты не
   только macOS и проверка `localtime_r` / часового пояса); при желании — подпись и нотаризация для macOS.
6. **Доступность и интерфейс:** AccessKit в вебе, масштабирование страницы, русский интерфейс (справочник уже
   двуязычный), ссылки «поделиться» с точками останова и watch.
7. **Совместимость:** `ENTER` / `BOUND` / `INS` / `OUTS` в ассемблере, `STRUC` / `IRP` в MASM, вложенные
   подстановки (пункт 20), видеорежимы CGA 4/5/6 и VGA 12h, звук PC speaker (порт 61h + PIT).
