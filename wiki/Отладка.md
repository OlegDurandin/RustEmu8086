# Отладка

**F9** (**▶ emulate**) собирает программу и загружает её в эмулятор. Дальше её можно выполнять целиком или по
шагам и смотреть, что происходит с регистрами, памятью и экраном.

## Шаги

| Клавиша | Кнопка | Что делает |
|---|---|---|
| **F8** | Single step | одна инструкция; на строке с макросом — заходит внутрь макроса |
| **F10** | Step over | строка целиком: макрос, `CALL` или `INT` выполняется за один шаг |
| **⇧F11** | Step out | выполнить до выхода из текущей процедуры или макроса |
| **⇧F8** или **F6** | Step back | шаг назад |
| **F4** | Run to cursor | выполнить до строки с курсором (или правый клик → *Run to line N*) |
| **F5** | Run / Stop | запуск и остановка; ползунок **step delay** замедляет выполнение |
| **F7** | show current instruction | показать текущую инструкцию |

**Шаг назад** возвращает регистры, память, экран, состояние устройств, клавиатуры, DOS и дискет — до 2000
инструкций назад. Операции с файлами на диске (создание, запись, удаление) откатить нельзя, поэтому на них
история обрывается.

`INT` — это один шаг: сервис BIOS или DOS выполняется целиком. Если программа ждёт клавишу, эмулятор
останавливается, пока вы её не нажмёте.

## Панели и окна

По умолчанию всё как в Emu8086: каждый инструмент — эмулятор, экран, память, стек, переменные, watch, точки
останова и другие — отдельное плавающее окно (**options → windows: classic windows (Emu8086)**); **reset** там
же возвращает окна на начальные места. При запуске открыт только редактор; окна эмулятора и инструменты, которые
были открыты в прошлый раз, появляются при **emulate**.

В **options → windows** можно выбрать **panels**: инструменты открываются вкладками рабочего пространства,
которые не перекрывают друг друга. Слева — редактор (рядом вкладки source, listing, справочник), посередине — эмулятор, под ним memory, watch,
ALU; справа — экран, а под ним то, что открывают кнопки эмулятора **vars**, **debug**, **stack**, а также журнал
и устройства; под редактором — breakpoints и call stack. Окно **flags** (и *lexical flag analyser*) — маленькое
плавающее, как в Emu8086.
Вкладку можно перетащить в другую группу или к краю соседней панели, границы между панелями — двигать,
крестик на вкладке закрывает инструмент. Расположение запоминается. **Emulator → Reset window layout** (или
кнопка **reset** в **options**) возвращает раскладку по умолчанию.

Диалоги (options, about, выбор
шаблона и т. п.) и таблица ASCII всплывают поверх в обоих режимах. В интерфейсе планшета инструменты всегда открываются окнами.

## Где видно состояние

- **Текущая строка** — стрелка ▶ в редакторе и подсветка в исходнике (вкладка **source**, в классическом
  режиме — окно **original source code**). Внутри макроса из
  `emu8086.inc` окно исходника показывает код библиотеки, а плашка сверху — откуда он вызван.
- **Регистры** — в окне **emulator**; изменившиеся за последний шаг выделены красным. Значение можно
  исправить прямо в поле. Двойной клик по имени регистра открывает **extended value viewer** — значение во
  всех системах счисления.
- **Подсказка в редакторе**: наведите мышь на регистр или переменную — покажется текущее значение.
- **Дизассемблер** — инструкции от CS:IP, у переходов подписаны имена меток (`CALL 0150h ; SCAN_NUM`).
  Данные программы (`DB`, `DW`, строки из макроса `print`) показаны как данные — `DB 'Hello', 0Dh, 0Ah, '$'`
  с именем переменной сверху, а нули после программы — одной строкой `DB 65219 DUP (0)`. Галочка **data as DB**
  под списком выключает это: тогда все байты читаются как инструкции, как их видит процессор. Если программа
  сама выполняет байты из данных, текущая инструкция всё равно показана как код.
  Список листается колесом мыши или полосой справа от него — по всему сегменту кода; кнопка **⌖ CS:IP** под
  списком, **F7** или следующий шаг возвращают к текущей инструкции.
  После завершения программы вместо списка — плашка «The program has terminated (exit code 0)»: CS:IP в этот
  момент указывает уже не в программу. Шаг назад возвращает к её последним инструкциям.

Кнопки внизу окна эмулятора — как в Emu8086:

| Кнопка | Окно |
|---|---|
| **screen** | экран эмулятора |
| **source** | исходник с текущей строкой |
| **reset** | загрузить программу заново |
| **aux** | память, ALU, stop on condition, таблица символов, листинг, breakpoints, watch, call stack, устройства, журнал |
| **vars** | переменные и константы (hex / dec / signed / bin / ascii) |
| **debug** | журнал состояния после каждой остановки и консоль в стиле DEBUG.EXE |
| **stack** | стек от SS:FFFE, текущий SP выделен |
| **flags** | флаги 0/1; **analyse** показывает, какие условные переходы сейчас выполнятся |

## Точки останова

- **В редакторе**: клик по полю слева от номера строки или **⌘F8**. Красная точка — обычная, оранжевая — с
  условием, серая — выключенная. При правке текста точки сдвигаются вместе со строками.
- **В дизассемблере**: двойной клик по инструкции.
- Окно **breakpoints** (*aux* → *breakpoints* или правый клик по строке → *Breakpoint condition…*):
  - **условие** для каждой точки: `cx == 0`, `[bx] > 10`, `al == 'A'`;
  - **счётчик срабатываний**, включение и выключение.
- Точки останова, условия, watch и закладки запоминаются для каждого файла и переживают перезапуск.

## Stop on condition

Как в Emu8086: выражение проверяется после каждой инструкции, и эмулятор останавливается, когда оно
**становится истинным** или **меняет значение**. Например, `[counter] == 0` или `sp < 0FFF0h` — чтобы поймать
переполнение стека. Окно — *aux* → *stop on condition* или меню **debug** окна эмулятора.

## Watch, call stack, ALU

- **watch** — выражения, которые пересчитываются после каждого шага; изменившиеся выделены красным. Добавить
  переменную из редактора: правый клик → *Add watch*.
- **call stack** — цепочка вызовов по адресам возврата `CALL` / `INT` в стеке, плюс макросы текущей строки.
  Клик по строке открывает её в редакторе.
- **ALU** — последняя арифметическая или логическая операция: операнды и результат в hex, двоичном и
  десятичном виде, флаги до и после.

## Выражения

В условиях, watch и stop on condition можно писать:

| Что | Примеры |
|---|---|
| регистры | `ax`, `al`, `ds`, `ip`, `sp` |
| флаги | `zf`, `cf`, `sf`, `of` … |
| переменные | `value`, `table[si]`, `offset msg` |
| память | `[bx]`, `word [si+2]`, `es:[di]` |
| числа | `10`, `0Ah`, `1010b`, `'c'` |
| операторы C | `+ - * / % << >> & \| ^ ~ ! == != < <= > >= && \|\|` |
| операторы ассемблера | `and or xor not shl shr mod` |

У NASM-программ имя — это адрес, а значение — в скобках: `count` — адрес, `[count]` — значение
(см. [Синтаксис NASM](Синтаксис-NASM)).

## Консоль DEBUG.EXE

Кнопка **debug** открывает журнал и командную строку в стиле DEBUG.EXE. Числа — в hex, адреса — `seg:off`,
линейные или `регистр:off`.

| Команда | Что делает |
|---|---|
| `r [reg [value]]` | показать регистры / изменить регистр |
| `d [addr] [len]` | дамп памяти (без адреса — продолжить) |
| `e addr b1 b2 …` | записать байты (или `'текст'`) |
| `f addr len byte` | заполнить память |
| `u [addr] [count]` | дизассемблировать |
| `t [n]` | выполнить n инструкций |
| `p` | step over |
| `g [addr]` | запустить (до адреса) |
| `h a b` | сумма и разность в hex |
| `cls` | очистить консоль |

## Меню окна эмулятора

- **file** — загрузить исполняемый файл, reload, примеры, сброс эмулятора и памяти, параметры командной строки
  программы (PSP:80h), **save the emulator's state** / **load from previous state** (снимок живёт до закрытия
  приложения).
- **debug** — шаги, stop on condition, **run until** (**⌃F8**) и **set CS:IP** (**⌃⇧F7**) для инструкции,
  выделенной кликом в дизассемблере.
- **view** — все окна; **virtual devices** — [устройства](Виртуальные-устройства); **virtual drive** —
  дискеты для INT 13h и диск C: (на Mac — *show drive C: folder*, в браузере — *drive C: files…*).

## Если код изменился

Правили текст после загрузки — окна эмулятора и исходника предупредят, что программа устарела. **F9** соберёт
и загрузит её заново; точки останова останутся на своих строках.
