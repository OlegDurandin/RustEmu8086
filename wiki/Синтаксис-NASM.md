# Синтаксис NASM

Кроме синтаксиса Emu8086, RustEmu8086 собирает программы на NASM — так же, как `nasm -f bin`: COM-программы,
загрузочные секторы и «чистые» двоичные файлы. Результат сверяется с настоящим NASM байт в байт.

```asm
bits 16
org 100h
    mov ah, 9
    mov dx, msg             ; in NASM a name is an address
    int 21h
    mov al, [count]         ; memory is read in brackets
    ret
msg   db 'Hello from NASM!', 13, 10, '$'
count db 3
```

## Как выбирается синтаксис

Автоматически. NASM включается, если в файле есть что-то из этого:

- `bits 16` / `[bits 16]`, `[org …]`, `section .text`, `cpu`, `global`;
- `%define`, `%macro`, `%include`, `%assign`, `%rep`, `%if`;
- `times`, `resb` / `resw` / `resd`, `$$`;
- размер без `ptr`: `byte [..]`, `word [..]`.

Ещё NASM выбирают расширение файла `.nasm` и строка `#nasm#`. Если программа не собирается в определённом
так синтаксисе, но собирается в другом, используется другой (например, `push word 5` или `` `a` `` без других
признаков NASM). Явно: меню **Options** или окно **options** → *assembler syntax* (auto / Emu8086 / NASM), в командной строке — `rustemu asm файл --syntax nasm`. Сообщение о сборке говорит,
каким синтаксисом собрана программа.

Заготовки: **new** → галочка *use NASM syntax* (COM, BIN, boot sector); примеры `hello_nasm.asm` и
`boot_nasm.asm` в **examples**.

## Главное отличие от Emu8086

В NASM имя — это адрес, а память читается только в квадратных скобках:

| Код | Emu8086 | NASM |
|---|---|---|
| `mov ax, value` | читает переменную | загружает адрес `value` |
| `mov ax, [value]` | читает переменную | читает переменную |
| `mov byte [bx], 5` | ошибка (нужно `byte ptr`) | так и пишется |
| `mov [bx], 5` | байт, если число помещается | ошибка: размер не указан |
| `mov ax, 'ab'` | AH = 'a', AL = 'b' | AL = 'a', AH = 'b' |

Отладчик это учитывает: в watch, условиях и подсказках `count` — адрес, `[count]` — значение.

## Формат программы

| `org` | Формат |
|---|---|
| `org 100h` | COM |
| `org 0x7c00` | загрузочный сектор (512 байт, запуск с 0000:7C00) |
| другой или нет | BIN |

Секции `.text`, `.data`, `.bss`: как в `nasm -f bin`, `.data` идёт после кода с выравниванием на 4 байта,
`.bss` занимает адреса после неё, но в файл не попадает.

## Что поддерживается

- `bits 16`, `use16`, `org`; `cpu`, `global`, `extern` принимаются и игнорируются.
- Метки с двоеточием и без, локальные метки `.loop` (в отладчике — `ПРЕДЫДУЩАЯ_МЕТКА.LOOP`).
- `db dw dd dq dt`, `times`, `resb … rest`, `align`, `alignb`, `equ`, `$`, `$$`.
- Числа `0x1F`, `1Fh`, `$1F`, `0b1010`, `1010b`, `0o17`, `17q`, `0d99`; строки `'…'`, `"…"` и `` `…` `` с
  `\n \t \r \0 \xHH`.
- Операнды `byte` / `word` / `dword` без `ptr`, `[es:di]`, `short` / `near` / `far`, `seg:off`.
- Операторы как в NASM, с его порядком: `?:`, логические `|| ^^ &&`, сравнения (истина — 1), затем `| ^ &`, сдвиги,
  `+ -`, `* / %`.
- Препроцессор: `%define` (в том числе с параметрами: `%define SQ(x) ((x)*(x))`), `%undef`, `%assign`,
  `%macro … %endmacro` с `%1…%9` и `%%метка`, `%rep`, `%if / %elif / %else / %endif`, `%ifdef`, `%ifndef`,
  `%include`, `%error`.
- Структуры: `struc … endstruc` (поля `.x resw 1` → смещение `имя.x`, размер `имя_size`) и `istruc … at … iend`.

```nasm
struc point
    .x: resw 1
    .y: resw 1
endstruc
    mov ax, [p + point.y]     ; 20
    mov cx, point_size        ; 4
p:  istruc point
        at point.x, dw 10
        at point.y, dw 20
    iend
```

## Чего нет

- Только `-f bin`. EXE для DOS в NASM собирается через объектный формат и компоновщик — этого нет; для EXE
  используйте [синтаксис Emu8086](Синтаксис-Emu8086).
- `%macro m 1+`, `%0`, `%rotate`, `%strlen` / `%substr`, `incbin`, числа с плавающей точкой в данных,
  произвольные имена секций, `%push` / `%$метка`.
- Дальние условные переходы собираются, как в Emu8086, парой «обратный короткий переход + `jmp near`»
  (у NASM без `cpu 8086` — инструкция 80386, которой нет у 8086), поэтому байты здесь отличаются от NASM.

Подробнее — вкладка *NASM syntax* во встроенном справочнике (**Help → NASM syntax**).
