# Процессор MIPS32

[English](MIPS32) · **Русский**

Кроме 8086, RustEmu8086 выполняет программы MIPS32 так же, как [MARS](https://github.com/dpetersanderson/MARS):
тот же синтаксис ассемблера, расположение памяти и системные вызовы. Это отдельное **рабочее место**: переключение
процессора не трогает программу для 8086, и наоборот.

## Как переключить процессор

- **Десктоп и веб на большом экране** — список слева в панели инструментов: *Intel 8086* / *MIPS32*.
- **Планшет** — значок рядом с именем файла в верхней панели (*8086 REAL MODE* / *MIPS32*).

У каждого процессора своя программа, несохранённые изменения, точки останова, watch, загруженная машина и открытые
окна. Переключение ставит выполняющуюся программу на паузу; когда вы вернётесь, всё будет как было. Приложение всегда
запускается в рабочем месте 8086; MIPS открывается переключателем или файлом, примером, ссылкой для MIPS.

Файл помнит свой процессор. Открытие файла, программы, сохранённой в браузере, или ссылки переключает на его рабочее
место. Файл, открытый впервые, попадает в текущее рабочее место, если только его текст явно не написан для другого
процессора (регистры MIPS вроде `$t0` и `syscall` или регистры 8086 вроде `ax`, `dl`) — тогда приложение спросит,
для какого он процессора.

## Первая программа

File → Examples → *Hello, MIPS* (в рабочем месте MIPS меню Examples показывает примеры MIPS, примеры 8086 — в
подменю, и наоборот). Или File → New:

```asm
        .data
msg:    .asciiz "Hello!\n"

        .text
main:   li   $v0, 4          # печать строки по адресу $a0
        la   $a0, msg
        syscall
        li   $v0, 10         # выход
        syscall
```

**emulate** (F9) собирает и загружает программу; дальше Step (F8), Step back (⇧F8), Run (F5) работают как для
8086. **compile** только проверяет программу: исполняемого файла у программ MIPS нет, как и в MARS.

## Почему код отличается от исходника

Как и в MARS, в списке кода — машинные инструкции (колонка *Basic* MARS), а не исходник. В исходнике могут быть
**псевдоинструкции** — `li`, `la`, `move`, `blt`, `mul` с константой… — которых у процессора нет; ассемблер заменяет
каждую одной или несколькими настоящими:

| Исходник | Машинные инструкции |
|---|---|
| `li $v0, 4` | `addiu $v0, $zero, 4` |
| `la $a0, msg` | `lui $at, 0x1001` + `ori $a0, $at, 0x0` (адрес метки двумя половинами, через `$at`) |
| `move $t0, $v0` | `addu $t0, $zero, $v0` |

Колонка source показывает строку у её первой инструкции; следующие инструкции той же строки отмечены `↳`.

## Окна

| Окно | Что показывает |
|---|---|
| emulator | кнопки выполнения, регистры и код: адрес, машинное слово, инструкция (**basic**), строка исходника; клик по ○ ставит точку останова |
| регистры | группами, по одной, **PC** — всегда под их вкладками: **GPR** — все 32 регистра общего назначения парами (`$zero $at`, `$v0 $v1`…; при наведении на имя — номер и назначение), **Special** — PC, HI, LO, **CP0** — BadVAddr, Status, Cause, EPC (только чтение; показан код последнего исключения), **FPU** — `$f0..$f31` парами, каждая пара ещё и как double, и 8 флагов условий (флаг меняется кликом); DEC показывает числа, HEX — их биты. Изменённые — красным; *HEX / DEC* переключает запись; на паузе значение меняется кликом (`$zero` всегда 0) |
| Run I/O | что печатает программа, и строка для её ввода: **Enter** (или *send*) передаёт строку программе |
| ALU | последняя арифметическая, логическая инструкция, сравнение, сдвиг, умножение или деление: операнды и результат (или HI и LO) в hex, двоичной, без знака и со знаком, переполнение; загрузки, сохранения, переходы и запись в `$zero` (`nop`) не показываются |
| memory | слова, по 16 байт в строке; кнопки *.text*, *.data*, *heap*, *$gp*, *$sp*, *PC*, *.kdata*; в поле адреса — hex (`0x10010000`) или выражение (`$sp`, `array + 8`). Адреса вне сегментов показаны как `········`: чтение оттуда — ошибка, а не ноль. На паузе клик по слову меняет его (hex `0x…` или десятичное, Enter) |
| variables | метки данных в размере своих данных (`.byte` / `.asciiz` — байты, `.half`, `.word`) |
| Keyboard and Display MMIO Simulator, Bitmap Display, Digital Lab Sim | инструменты MARS для устройств в памяти (меню *tools* окна эмулятора; см. ниже) |
| source, listing, symbol table, watch, breakpoints, call stack, stop on condition | как для 8086; листинг — text segment MARS: адрес, код, базовая инструкция, исходник |

Окна, которые есть только у 8086, — экран, флаги, FPU, окно стека, виртуальные устройства, диск C:, консоль
DEBUG.EXE и библиотека emu8086.inc — в рабочем месте MIPS не показываются.

В отладчике и watch регистры пишутся как в исходнике: `$t0`, `$8`, `$sp + 4`, `$f12` (его биты), `fcc`
(флаги условий байтом); метка даёт свой адрес, `[метка]` и
`dword [метка]` — значение в памяти.

## Планшет

Те же три вкладки: **Editor** (исходник, вывод, регистры), **Debugger** (последний шаг — инструкция и изменённые ею
регистры и байты; код; регистры; watch, точки останова, стек вызовов) и **Memory** (память и переменные). Карточка
вывода показывает **Run I/O** со строкой ввода; PC-клавиатура программам MIPS не нужна.

## Справочник

**Help** (или кнопка *help*, F1) открывает справочник MIPS32; переключатель вверху показывает справочник 8086 или
MIPS, *EN / RU* — язык:

- **инструкции** — все машинные инструкции и псевдоинструкции, которые принимает MARS, по группам, статьями на
  семейство (`lb / lbu`, `blt / ble / bgt / bge…`): что делает, исключения, пример; и **формы** так, как их пишет
  таблица MARS, у каждой псевдоинструкции — машинные инструкции, в которые она собирается
  (`li $t1,100000 → lui $at, 0x1; ori $t1, $at, 0x86a0`);
- **системные вызовы** — все сервисы `syscall` MARS по номерам: аргументы, результаты, примечания, пример; ещё не
  поддержанные — серые;
- **директивы** — `.text`, `.data`, `.word`, `.asciiz`, `.align`, `.eqv`…;
- **регистры и память** — 32 регистра с номерами и соглашениями, PC / HI / LO, регистры `$f` и флаги условий
  сопроцессора 1, карта памяти MARS.

В редакторе при наведении на инструкцию, директиву или `syscall` появляется краткое описание (сервис `syscall`
берётся из `li $v0, n` перед ним); F1 или ⌘-клик открывает статью.

## Командная строка

`rustemu asm / run / disasm` работают и с программами MIPS: файлы `.s` и исходники для MIPS распознаются,
`--arch mips` задаёт явно. См. [Командная строка](Командная-строка).

## Что поддерживается

- Инструкции MARS — 77 целочисленных и сопроцессора 1 — и его псевдоинструкции, директивы `.text .data .ktext
  .kdata .word .half .byte .float .double .ascii .asciiz .space .align .extern .globl .eqv .set`, `%hi` / `%lo`.
- Системные вызовы 1–17, 30–36, 40–44 и диалоги 50–59: печать (и чисел float и double), ввод, `sbrk`, выход, файлы (на диске C:, общем с программами
  DOS: на Mac — его папка, в браузере — окно **drive C:**, там файлы сохраняются и скачиваются), время, `sleep`, случайные числа.
- Исключения (переполнение, невыровненный доступ, адрес вне сегментов, ловушки) и обработчик по адресу `0x80000180`.
- Плавающая точка как в MARS: `float` — в одном регистре, `double` — в чётном регистре и следующем (нечётный
  останавливает программу, как в MARS), округления, преобразования, сравнения в 8 флагов условий. Сверено с MARS
  на случайных программах: регистры, флаги, память и ошибки совпадают.
- Макросы и `.include` по правилам MARS (см. ниже).
- Устройства MARS в памяти: Keyboard and Display MMIO Simulator, Bitmap Display и Digital Lab Sim (см. ниже).
- Настройки MARS: отложенные переходы, самомодифицирующийся код, старт с `main`, запрет псевдоинструкций,
  предупреждения как ошибки, компактные конфигурации памяти, ввод в диалогах, аргументы программы, файл обработчика
  исключений и программы из нескольких файлов (см. ниже).

Пока нет: других инструментов MARS (Data Cache Simulator, BHT Simulator, Instruction Statistics, MIPS X-Ray…).

## Диалоги (syscall 50–59)

Диалоговые сервисы MARS открывают окно, и программа ждёт ответа, как в MARS:

| `$v0` | окно | результат |
|---|---|---|
| 50 | сообщение из `$a0`, Yes / No / Cancel | `$a0` = 0, 1, 2 (−1: окно закрыто) |
| 51, 52, 53 | сообщение и поле для целого, float, double | `$a0` / `$f0`, и `$a1` = 0 OK, −1 не число, −2 Cancel, −3 ничего не введено |
| 54 | сообщение и поле для строки в буфер `$a1` размером `$a2` байт | буфер (перевод строки, если есть место, нулевой байт), `$a1` = 0, −2, −3 или −4, если строка длиннее |
| 55 | сообщение; `$a1`: 0 ошибка, 1 информация, 2 предупреждение, 3 вопрос | — |
| 56, 57, 58, 59 | сообщение и после него `$a1`, `$f12` (float или double) или строка из `$a1` | — |

Числа разбираются, как в Java: целое — без пробелов вокруг (Integer.parseInt), float — с пробелами, `NaN`,
`Infinity`. В командной строке окон нет: сообщение печатается, а вопрос или ввод берёт строку ввода (для 50:
`y`, `yes` или `0` — да, `n`, `no` или `1` — нет, иное — отмена).

## Макросы и .include

```asm
.include "print_macros.s"        # print_int, print_str, done

.macro for (%reg, %from, %to, %body)
        add  %reg, $zero, %from
loop:
        %body ()
        add  %reg, %reg, 1
        ble  %reg, %to, loop
.end_macro
```

- `.macro имя (%a, %b)` … `.end_macro`; вызов — `имя (x, y)` или `имя x y`. Параметры начинаются с `%` (подходит
  и `$a` в стиле SPIM); аргумент — одна лексема: регистр, число, метка, строка.
- Макрос определяется до использования. Макросы с одним именем и разным числом параметров — разные; из двух с
  одинаковым числом берётся последний.
- Метка в теле в каждой развёртке становится `label_M0`, `label_M1`…, поэтому цикл можно развернуть много раз.
- `.include "файл"` заменяет свою строку файлом; относительное имя берётся из папки включающего файла. В приложении
  файл ищется ещё на диске C: и среди файлов встроенных примеров (`print_macros.s` — см. пример *macros and
  .include*). Повторное включение того же файла — ошибка, как в MARS.
- Список кода показывает каждую строку развёртки как MARS: `21: <13> la $a0, text_M0` — строка 21 вызывает
  макрос, 13 — строка его тела. Шаг заходит в тело (и во включённом файле); ошибки в развёртке пишутся как
  `line 21->13`.

## Устройства в памяти

Меню *tools* окна эмулятора (и *Windows* в меню Emulator, ⋮ на планшете) открывает инструменты MARS для ввода и
вывода через память. Они всегда подключены: программа может пользоваться ими без кнопки «Connect to MIPS».
Программа, которая обращается к устройствам (в её коде адрес строится через `lui …, 0xffff`), открывает при
**emulate** окно клавиатуры и дисплея или Digital Lab Sim. Адреса ниже — конфигурации памяти по умолчанию; в
компактных устройства на тех же смещениях от `0x7f00` (см. [Настройки MARS](#настройки-mars)).

**Keyboard and Display MMIO Simulator** — четыре слова с адреса `0xffff0000`:

| адрес | регистр |
|---|---|
| `0xffff0000` | управление приёмником: бит 0 — есть клавиша, бит 1 — разрешение прерывания |
| `0xffff0004` | данные приёмника: клавиша (чтение сбрасывает бит готовности) |
| `0xffff0008` | управление передатчиком: бит 0 — дисплей готов, бит 1 — разрешение прерывания |
| `0xffff000c` | данные передатчика: символ для дисплея |

Щёлкните область KEYBOARD и печатайте: каждая клавиша попадает в приёмник. Символ, записанный в передатчик, пока
дисплей готов, появляется после задержки (*Delay length*, по умолчанию 5 инструкций; без *DAD* — сразу), затем
дисплей снова готов. *Delay* выбирает постоянную задержку или, как в MARS, случайную: равномерно от 1 до длины или
`floor(abs(N(0,1) * длина) + 1)`. Символ 12 очищает дисплей; символ 7 превращает его в терминал размером с окно и
ставит курсор в столбец из битов 20..31 и строку из битов 8..19 записанного слова. Если установлен бит 1 регистра
управления (и бит 0 Status, как после запуска), клавиша или готовность дисплея прерывают программу: обработчик по
адресу `0x80000180` получает в Cause код 0 с битом 8 (клавиатура) или 9 (дисплей), `eret` возвращает. *Reset*
очищает дисплей и делает передатчик готовым. См. пример *keyboard and display (MMIO)*.

Как и в MARS, устройство хранит одну клавишу: клавиша, нажатая до того, как программа прочитала предыдущую,
заменяет её. Если несколько клавиш приходят сразу (быстрый набор, вставка), окно передаёт их программе по одной —
каждую после того, как прочитана предыдущая.

**Bitmap Display** — слова памяти как пиксели, строка за строкой от базового адреса (по умолчанию `0x10010000`,
static data), каждое — `0x00RRGGBB`. В окне задаются единица (одно слово) и размер дисплея в пикселях: 512 x 256
при единице 1 x 1 — это 512 x 256 слов. Показывается память как она есть сейчас — и после шага назад; MARS
закрашивает единицу, когда программа её записывает. См. пример *bitmap display*.

**Digital Lab Sim** — байты с адреса `0xffff0010`: два семисегментных индикатора, шестнадцатеричная клавиатура 4 x 4
и счётчик.

| адрес | |
|---|---|
| `0xffff0010`, `0xffff0011` | правый и левый индикатор: бит 0 — сегмент a … бит 6 — g, бит 7 — точка |
| `0xffff0012` | строка для опроса (1, 2, 4, 8); биты 4..7 разрешают прерывание клавиатуры |
| `0xffff0013` | не ноль — прерывание счётчика |
| `0xffff0014` | клавиша, найденная в этой строке: бит строки + бит столбца << 4 (клавиша 2 — `0x41`), 0 — нет |

Щелчок нажимает клавишу; следующий щелчок (по любой клавише) отпускает её. Счётчик прерывает программу после
каждых 31 уведомления MARS: инструкций, выбранных из `.text` (не из обработчика в `.ktext`), и чтений и записей
`0xffff0010..13`. Его прерывание (бит 10 Cause) и прерывание клавиатуры (бит 11) приходят всегда, когда программа
не в обработчике, — разрешение прерываний в Status не важно, — а эти биты Cause остаются установленными, как в
MARS. Чтение `0xffff0010` тоже зажигает индикатор; слово или полуслово, записанное туда, видно только по первому
байту. См. пример *digital lab sim*.

Клавиатура и дисплей и Digital Lab Sim сверены с инструментами самого MARS: тот же текст дисплея, сегменты,
регистры и прерывания для программ, которые опрашивают устройства, принимают прерывания, пользуются терминалом и
получают клавиши или щелчки после заданных инструкций.

## Настройки MARS

Меню *settings* окна эмулятора (а также Options → *MARS settings* и *all options…*, на планшете ⋮ → Options)
содержит настройки MARS, которые меняют сборку и выполнение программы. Они сохраняются и действуют со следующего
**emulate**; загруженная программа выполняется с теми настройками, с которыми собрана, а после их смены окно
эмулятора говорит об этом и предлагает *Reassemble and load (F9)*.

| настройка | ключ MARS | что меняется |
|---|---|---|
| Delayed branching | `db` | инструкция после перехода (слот задержки) выполняется до того, как переход сработает; `jal`, `jalr`, `bgezal`, `bltzal` пишут адрес возврата за слотом; псевдоинструкции получают `nop` своих слотов (`mulo`, `mulou`…). В списке кода у инструкции в слоте задержки видно, куда переход пойдёт дальше |
| Self-modifying code | `smc` | программа читает и пишет text-сегмент, записанное слово становится инструкцией (и за концом программы); код выполняется из сегмента данных (`jalr` на данные) |
| Initialize Program Counter to global 'main' if defined | `sm` | выполнение начинается с `main`, если программа объявила `.globl main` |
| Permit extended (pseudo) instructions and formats | `np` выключает | без неё `li`, `la`, `move`, `lw $t0, label`… — ошибки («Extended (pseudo) instruction or format not permitted.  See Settings.») |
| Assembler warnings are considered errors | `we` | предупреждение (значение `.byte` вне диапазона…) останавливает сборку |
| Popup dialog for input syscalls (5,6,7,8,12) | — | сервисы чтения спрашивают в окне «MIPS Keyboard Input», а не в консоли Run I/O; в консоли — `**** user input : …`, как в MARS |
| Program arguments provided to MIPS program | `pa` | аргументы (через пробел) кладутся под стек при каждой загрузке: `$a0` — их число, `$a1` — адрес массива их адресов, `$sp` — ниже него |
| Assemble all files in directory | `p` | файлы `.asm` и `.s` папки программы собираются вместе с ней (см. ниже; не в браузере) |
| Exception handler | — | этот файл собирается первым с каждой программой, его код в `.ktext` обрабатывает исключения (не в браузере) |
| Memory configuration | `mc` | где сегменты, см. ниже |

Как в MARS, некоторые подробности — его собственные:

- переход в слоте задержки сохраняет цель первого перехода и выполняет его на инструкцию позже;
- исключение в слоте задержки входит в обработчик, но отложенный переход срабатывает сразу после этого, и код
  обработчика не выполняется;
- при самомодифицирующемся коде text-сегмент читается и пишется словами: запись байта или полуслова заменяет всё
  слово, чтение байта или полуслова берёт младшие биты слова, а по адресу не слова и то и другое — ошибка адреса
  («fetch address for text segment not aligned to word boundary»).

Конфигурации памяти:

| | Default | Compact, Data at Address 0 | Compact, Text at Address 0 |
|---|---|---|---|
| `.text` | `0x00400000` | `0x00003000` | `0x00000000` |
| `.data` | `0x10010000` | `0x00000000` | `0x00002000` |
| куча (`sbrk`) | `0x10040000` | `0x00002000` | `0x00003000` |
| `$gp` / `$sp` | `0x10008000` / `0x7fffeffc` | `0x00001800` / `0x00002ffc` | `0x00001800` / `0x00003ffc` |
| `.ktext` / обработчик исключений | `0x80000000` / `0x80000180` | `0x00004000` / `0x00004180` | `0x00004000` / `0x00004180` |
| `.kdata` | `0x90000000` | `0x00005000` | `0x00005000` |
| MMIO (устройства) | `0xffff0000` | `0x00007f00` | `0x00007f00` |

В компактной конфигурации любой адрес помещается в 16 бит: `la`, `lw $t0, label` и другие псевдоинструкции с меткой
занимают одну инструкцию вместо двух, как в MARS. Кнопки окна памяти, базовые адреса Bitmap Display и устройства
следуют конфигурации загруженной программы.

С *Assemble all files in directory* или файлом обработчика программа состоит из нескольких файлов и собирается, как
в MARS: сначала обработчик, затем программа, затем остальные файлы (`.asm` раньше `.s`, по имени). У каждого файла
свои метки, макросы и `.eqv`; метку, объявленную `.globl` (и данные `.extern`), видят все файлы, вторая глобальная
метка с тем же именем — ошибка; `.text` и `.data` продолжаются из файла в файл. Список кода и окно исходника
показывают строки всех файлов.

В командной строке — те же настройки: `--delayed-branching`, `--self-modifying`, `--start-at-main`, `--no-pseudo`,
`--warnings-are-errors`, `--memory <конфигурация>`, `--project`, `--exception-handler <файл>`,
`--program-args <текст>` (см. [Командная строка](Командная-строка)).

Настройки, программы из нескольких файлов, аргументы программы и сервисы ввода сверены с MARS, запущенным с теми же
ключами и файлами: случайные программы с отложенными переходами (переходы и ловушки в слотах задержки, `jal`,
`jalr`), программы для каждой настройки, собранные код и данные нескольких файлов с ошибками MARS. Диалоговые окна
сделаны по исходникам MARS (его окна Swing тестом не управляются). Так как два режима MARS здесь расходятся, символ
(syscall 12) и строка длиннее буфера читаются так, как их читает окно Run I/O MARS: клавиша без Enter; ввод
кончается, когда буфер заполнен.

## Отличия от MARS

RustEmu8086 выполняет программы MIPS как MARS 4.6 и сверен с ним (см. выше). Где он делает иначе — нарочно или
потому, что способ MARS связан с его собственными окнами:

| | MARS | RustEmu8086 |
|---|---|---|
| Строки в исходнике и вводе | младший байт каждого символа | UTF-8 (кириллица, символы); ASCII — то же самое |
| `%hi(label)` / `%lo(label)` | не поддерживаются | принимаются, как в GNU as |
| `swr $t1,100` | в его таблице забыт `($1)`: вторая инструкция — `nop` | `swr` с `($1)`, как остальные формы |
| После ошибки выполнения | PC — за инструкцией | PC остаётся на ней (список кода показывает, где ошибка) |
| Устройства в памяти | подключаются кнопкой «Connect to MIPS» | подключены всегда |
| Клавиатура MMIO | клавиша, набранная до чтения предыдущей, заменяет её | окно копит набранное и отдаёт по одной, когда программа прочитала предыдущую |
| Bitmap Display | рисует клетку при записи программы | показывает память как есть (и после шага назад) |
| Ввод в командной строке (`nc`) | строка на каждое чтение | как окно Run I/O MARS: символ без Enter, строка кончается, когда буфер заполнен |
| Диалоги (50–59) в командной строке | окна Swing | сообщение печатается, ответ — строка ввода |
| Аргументы программы | кладутся при запуске | кладутся при загрузке (видны в регистрах до запуска) |
| Файловый ввод-вывод (14, 15) | без наших ресурсных лимитов | чтение до 64 КиБ за вызов (возможен короткий результат); запись до 16 МиБ за вызов, для файлов — ещё и общая квота 16 МиБ за запуск; превышение — −1 в `$v0` |
| Ресурсные лимиты сборки | без наших общих бюджетов | до 250 000 исходных и генерируемых строк вместе, 4 МиБ исходников, 16 МиБ развёртки, 1024 файла, путь 4 КиБ, строка 64 КиБ / 4096 токенов, 1 млн обработанных токенов, до 100 диагностик. Include и файлы проекта входят в общий бюджет; превышение останавливает сборку |
| Создание файлов (13) | без нашего лимита создания | до 1024 новых файлов за запуск; существующие доступны после лимита. Диск в памяти — 2 МиБ и 1024 файла/папки, включая существующие пустые папки; отказ открытия/записи — −1 до изменения данных |
| Генераторы случайных чисел (40–44) | без нашего лимита потоков | до 4096 потоков; новый сверх лимита — исключение syscall, существующие продолжают работать |
| MIDI (31, 33) | звучит | без звука (33 ждёт длительность) |
| Assemble all files in directory | порядок папки (как его даёт система) | файлы `.asm`, затем `.s`, по имени |
| Файл обработчика исключений, все файлы папки | везде | в приложении для Mac и командной строке (в браузере нет папок) |
| Другие инструменты | Data Cache Simulator, BHT Simulator, Instruction Statistics, MIPS X-Ray, Floating Point Representation… | нет |
| Настройки редактора и окон | MARS | свои (темы, панели, справочник) |
