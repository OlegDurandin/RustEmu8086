# Для разработчиков

[English](For-developers) · **Русский**

RustEmu8086 написан на Rust (edition 2024), интерфейс — [egui / eframe](https://github.com/emilk/egui) 0.37 с
рендерером wgpu: Metal на macOS, WebGPU или WebGL 2 в браузере. Лицензия — MIT.

## Сборка

Нужны macOS 11+ и Rust 1.95+ (`curl https://sh.rustup.rs -sSf | sh`, обновление — `rustup update`).

```sh
cargo run --release -p rustemu-desktop                       # the app
cargo run --release -p rustemu-desktop -- examples/hello.asm  # open a file
cargo run -p rustemu-tablet                                  # tablet layout in a Mac window
./scripts/bundle_macos.sh                                    # RustEmu8086.app + zip
UNIVERSAL=1 ./scripts/bundle_macos.sh                        # Apple Silicon + Intel
```

### Веб-версия

```sh
rustup target add wasm32-unknown-unknown
brew install trunk               # or: cargo install trunk
cd crates/rustemu-web
trunk serve                      # http://127.0.0.1:8080
trunk build --release            # site in crates/rustemu-web/dist/
```

Сборка идёт с профилем cargo `web`: оптимизация по размеру и LTO, ядро эмулятора — по скорости. Эмодзи-шрифты
урезаны до символов интерфейса — после нового значка в интерфейсе запустите `scripts/subset_emoji_fonts.py`
(тест `web_fonts_cover_the_ui` напомнит). Для подпапки: `trunk build --release --public-url /RustEmu8086/`.

## Устройство

| Крейт | Что внутри |
|---|---|
| `rustemu-target` | граница между процессором и остальным: трейт `Target` (шаги, шаг назад, точки останова, память, дизассемблер, регистры по имени). Без зависимостей |
| `rustemu-core` | процессор 8086 (+ расширения 80186), память 1 МБ, `Machine` (загрузка, шаги, шаг назад, точки останова), BIOS, DOS, видео, устройства, дизассемблер; `Machine` реализует `Target`. Без зависимостей от GUI |
| `rustemu-mips` | MIPS32: целочисленные инструкции, память и исключения как в MARS, его системные сервисы (`syscall`), текстовая консоль, файлы в песочнице, шаг назад; ассемблер диалекта MARS и дизассемблер; `impl Target` |
| `rustemu-asm` | ассемблер Emu8086 / MASM и NASM: препроцессор, многопроходная сборка, кодирование, листинг; встроенный `emu8086.inc` |
| `rustemu-session` | связка ассемблера и эмулятора через `Target`: строка исходника ↔ адрес, выражения отладчика, стек вызовов, Step Over / Out; часть 8086 (форматы программ, дискеты) — в `x86.rs` |
| `rustemu-cli` | программа `rustemu` |
| `rustemu-ui` | общая часть интерфейса: состояние приложения, редактор, экран, окна отладки, справочник |
| `rustemu-desktop` | интерфейс в стиле Emu8086, программа для macOS |
| `rustemu-tablet` | интерфейс планшета и экранная клавиатура |
| `rustemu-web` | веб-версия: обе раскладки, переключение на лету |

Главные решения:

- **Граница архитектуры.** Session и общая часть интерфейса (цикл выполнения, точки останова, watch, стек вызовов,
  список дизассемблера, дамп памяти) работают с любым процессором через трейт `Target`; окна 8086 (регистры
  Emu8086, флаги, FPU, экран, устройства, диски, консоль DEBUG.EXE) получают `Machine` через `x86()`, окна MIPS
  (`rustemu_ui::mips_ui`) — машину MIPS через `mips()`. Новая архитектура — свой крейт с `impl Target`, ветки
  `match arch` в session и свои окна.
- **Рабочее место на процессор** (`rustemu-ui/src/app/arch.rs`). У каждой архитектуры свой документ, сессия,
  состояние отладчика и окна; `App::switch_arch` паркует одно и возвращает другое. Архитектура принадлежит
  документу (сохранённая сессия, программа браузера, `&arch=` в ссылке); `App::has_tool` — какие окна есть у
  процессора.
- **Прерывания «настоящие».** Таблица векторов в 0000:0000 указывает на заглушки в ROM (`F000:1000 + 4·n`):
  служебный опкод `0F FF nn` и `IRET`. На нём эмулятор вызывает обработчик BIOS / DOS на Rust. Программы могут
  перехватывать векторы.
- **Видеопамять — в адресном пространстве** (`B800:0000`, `A000:0000`), состояние видео — в BIOS Data Area;
  интерфейс только рисует память.
- **Шаг назад**: на каждую инструкцию — снимок регистров и журнал перезаписанных байт; устройства, DOS и
  очереди — только для инструкций, которые могут их менять.
- **Загрузка**: PSP в `0700h`; COM — `0700:0100`; EXE — с `0710h`; BIN — `#load_segment#` (по умолчанию
  `0100h`); BOOT — `0000:7C00`.

## Тесты

```sh
cargo test --workspace
cargo test -p rustemu-desktop -p rustemu-tablet   # UI tests, PNG snapshots in target/ui-snapshots/
```

- **NASM**: если установлен `nasm` (`brew install nasm`), ~18 000 кодировок инструкций и целые NASM-программы
  сверяются с ним байт в байт.
- **Примеры Emu8086** (папка `examples`, файлы из поставки Emu8086 без изменений):
  `cargo test -p rustemu-session --test emu8086_corpus -- --nocapture` собирает и запускает все 84 примера.
  Наши тестовые программы — в `tests/programs`.
- **MARS** (ядро MIPS): случайные программы выполняются на ядре и в настоящем MARS и сравниваются — регистры,
  HI/LO, память, исключения; машинный код и данные ассемблера против MARS по каждой форме каждой инструкции:
  `MARS=<Mars.jar или папка с Mars.class> cargo test -p rustemu-mips --test mars_compare -- --nocapture`.
- **binutils** (ассемблер MIPS): каждая базовая форма со случайными операндами собирается RustEmu8086 и
  `mipsel-linux-gnu-as` и сравнивается слово в слово, если binutils установлены (`brew install
  mipsel-linux-gnu-binutils`).
- **objdump** (дизассемблер MIPS): каждая базовая форма декодируется в ту же инструкцию и те же значения операндов,
  что у `mipsel-linux-gnu-objdump`, и обратно в текст ассемблера.
- **SingleStepTests 8088**: ~2,9 млн тестов, снятых с реального процессора. Скачайте `v2/*.json.gz` и
  `v2/metadata.json` из [SingleStepTests/8088](https://github.com/SingleStepTests/8088) в `testdata/8088/`,
  затем `cargo test -p rustemu-core --release --test singlestep -- --ignored`. Любое изменение процессора
  проверяется на них.

## Правила

- `cargo fmt` и `cargo clippy --workspace -- -D warnings` (и для `--target wasm32-unknown-unknown`) — без
  предупреждений; это проверяет CI.
- У каждого публичного элемента — doc-комментарий (`#![warn(missing_docs)]`); `cargo doc` с
  `RUSTDOCFLAGS=-D warnings` проверяет CI.
- Комментарии в коде — на английском. README и вики — на английском и русском: меняя одно, правьте и другое.
- Работа — в ветках, в `main` — через слияние.

## CI и выпуск

- `.github/workflows/ci.yml` — fmt, clippy, документация, тесты на macOS; на `main` — сборка `.app` и публикация сайта на
  GitHub Pages.
- `audit.yml` — `cargo audit` при изменении зависимостей и раз в неделю.
- `wiki.yml` — публикует страницы из папки `wiki/` в вики GitHub при push в `main`. Правьте вики в репозитории:
  правки на сайте GitHub следующая публикация перезапишет.
- Выпуск: версия в `Cargo.toml` (`[workspace.package] version`), затем тег `vX.Y.Z` → `release.yml` публикует
  релиз; описание — из `release-notes/vX.Y.Z.md`.
