# Интерфейс планшета

На iPad и других планшетах RustEmu8086 работает через [веб-версию](Веб-версия): в браузере она сама выбирает
интерфейс для касаний. Отдельного приложения для iPadOS и Android нет — браузер даёт то же самое без установки.
Сайт можно добавить на экран «Домой»: Safari → «Поделиться» → «На экран Домой».

Тёмная тема, крупные элементы под палец.

## Верхняя панель

Имя файла и кнопки **Run / Pause / Step / Reset**. Run, Step и Reset сами собирают программу, если текст
изменился.

Касание имени файла открывает **меню проекта**:

- **New ASM file** — новый файл: пустой или по шаблону;
- **Open from Files…** — исходник (`.asm`, `.inc`) или готовая программа (`.com`, `.exe`, `.bin`) из «Файлов»
  iPad или с диска компьютера;
- **Example library** — каталог примеров с поиском и описаниями;
- **Save draft** — сохранить программу в этом браузере (только на этом устройстве и в этом браузере, это не
  «Файлы»); **My drafts** — сохранённые программы;
- **Export .asm** — скачать исходник файлом;
- **Share source** — отправить `.asm` через системное меню «Поделиться» (AirDrop, «Сообщения», почта…). Если
  браузер не умеет делиться файлами, исходник скачивается, и об этом пишет строка состояния.

Несохранённые изменения перед New / Open не теряются: появится вопрос Save / Discard / Cancel.

## Вкладки

У каждой вкладки одна главная область и её контекст.

- **Editor** — исходник (около 60% ширины в альбомной ориентации), справа **Output** (экран эмулятора или
  сообщения ассемблера) и краткий **CPU**: AX, BX, CX, DX вместе с байтами (AH | AL …), флаги CF ZF SF OF,
  сегментные регистры, ссылка *Open debugger*.
- **Debugger** — разбор одного шага:
  - **Last step** — последняя выполненная инструкция и её строка, что она изменила (`BL 0Fh → 0Eh`,
    `BX 000Fh → 000Eh`, `CF 0 → 1`, записанные байты памяти) и справа строка следующей команды.
    *Why did this happen?* объясняет флаги (`SUB 0Fh − 01h = 0Eh`, `ZF = 0 (result is not 0)` …),
    *Open ALU details* открывает подробности АЛУ;
  - **Code** — *Source* (исходник, по умолчанию), *Mixed* (каждая строка исходника над своими инструкциями),
    *Assembly*. Последняя выполненная строка отмечена синей полосой, следующая (CS:IP) — янтарной стрелкой;
    касание поля слева ставит точку останова;
  - **CPU** — AX–DX в одной ячейке: сверху слово (AX 001F), снизу его байты (AH 00 │ AL 1F), SP BP SI DI, CS DS ES SS и IP, все девять флагов;
  - кнопки **Watch, Breakpoints, Call stack, Trace, ALU, Debug log** открывают один инструмент под кодом (повторное
    касание закрывает). Если Output не помещается рядом с CPU (iPad 10–11″ в альбомной ориентации, узкое окно),
    он тоже становится такой кнопкой.
- **Memory** — hex-редактор (сегмент, переход к адресу, поиск байтов или текста, ввод в HEX или ASCII, 8/16/32
  байта в строке), инспектор байта, сегментные регистры, стек, карта 1 МБ памяти.

В альбомной ориентации — две колонки, в портретной и в узком окне (Split View) — главная область сверху,
контекст под ней.

### Регистры и флаги

Изменившееся за последний шаг (или за последний запуск Run) значение выделено зелёным и точкой в углу.
Касание слова регистра (верхняя строка ячейки), его байта или флага показывает значение в HEX, десятичном и двоичном виде (флаг — с
описанием). Пока программа на паузе, значение можно изменить: байт меняет только свою половину регистра
(AL = AA при AX = 1234 даёт AX = 12AA). Во время работы и пока программа ждёт клавишу — только просмотр.

### Ожидание клавиши

Когда программа ждёт ввода (INT 16h, INT 21h), в Output написано, где именно: *Waiting for a key — INT 21h at
echo.asm:10*, и есть кнопка *Open keyboard*. Code показывает строку программы с этим `INT`, а не код BIOS;
внутренности BIOS — галочка *BIOS internals*. Step во время ожидания недоступен: сначала нужна клавиша. Если
программа остановилась на шаге, который ждёт клавишу, нажатие на PC-клавиатуре этот шаг и завершает.

## PC-клавиатура

Клавиатура эмулируемого компьютера: нажатия уходят в программу (в буфер клавиатуры BIOS), а не в редактор.
Код в редакторе набирается обычной клавиатурой планшета. Панель прикреплена снизу и занимает около трети
высоты экрана; Output остаётся над ней. Открывается значком клавиатуры рядом с ⋮, кнопкой *Open keyboard*,
касанием экрана эмулятора и сама, когда программа начинает ждать ввода (один раз — после *Hide* она не
появляется снова до следующего ожидания).

- Раскладка US и клавиши для DOS-программ: Esc, Tab, Ctrl, стрелки, по **Fn keys** — F1–F10,
  Ins / Del / Home / End / PgUp / PgDn.
- Shift и Ctrl действуют на одну следующую клавишу.
- *Hide* убирает панель, но не отменяет ожидание.
- На вкладке Memory рядом с клавишами — небольшой экран эмулятора.

## Меню ⋮

- примеры (меню Examples, как в Emu8086) и **Share link…** — ссылка на программу в веб-версии;
- отладка: Assemble and load, Step back, Step over, Step out, Run to cursor;
- **Virtual drive** — диск C: (в браузере — его файлы, в окне на Mac — папка) и дискеты: загрузка с дискеты,
  запись boot-сектора и `.bin`-файла, новая дискета — как в меню *virtual drive* интерфейса Emu8086;
- окна: **Drive C: files** (в браузере), Virtual devices, Variables, Symbol table, Listing, ALU, Stop on condition;
  **Debug log** — консоль в стиле DEBUG.EXE на вкладке Debugger;
- инструменты: Reference, Calculator, Base converter, ASCII codes;
- *Desktop layout* — переключение на интерфейс Emu8086; **Options** — синтаксис ассемблера (auto / Emu8086 /
  NASM) и *all options…*; About.
