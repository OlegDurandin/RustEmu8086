# Синтаксис A86

[English](A86-syntax) · **Русский**

RustEmu8086 поддерживает исходный диалект A86 для программ 8086/80186. У A86 свои правила записи чисел,
типизированных операндов, локальных меток и макросов; правильный выбор диалекта важен даже для коротких программ.
В том числе поддерживается работа с листингами для реального режима из книги
«Ассемблер и программная модель x86/64» в пределах описанных ниже ограничений совместимости.

## Выбор A86

Выберите **Options → assembler syntax → A86** или оставьте **auto**. Расширения `.a86`, `.8`, `.08`, `.8x`
и маркер `#a86#` в исходнике включают A86 автоматически. При ошибке такой исходник не пересобирается
в MASM/NASM: иначе константа вроде `0100` могла бы незаметно поменять значение.

```sh
rustemu asm program --syntax a86 -o program.com
rustemu run examples/hello_a86.a86 --max 1000
```

`--syntax` — параметр сборки. Команда `run` определяет A86 по расширению или маркеру в исходнике;
в переносимом проекте можно явно сохранить `"dialect": "A86"`.

## Попробуйте пример

Откройте **examples → Hello, world (A86)**, нажмите **F9** и **F5** или выполняйте программу по шагам (**F8**).
Исходник — `examples/hello_a86.a86`. Он выводит `Hello from A86!` и завершается с кодом 0.
Макрос `clear` раскрывает один вызов в три инструкции `XOR`:

```asm
#a86#
clear macro
#rx1l
    xor #x, #x
#em

    clear ax, bx, dx
    mov dx, offset message
    mov ah, 09
    int 021
    mov ax, 04c00
    int 021
message db 'Hello from A86!', 0d, 0a, '$'
```

## Что поддерживается

- Числа с ведущим нулём — шестнадцатеричные: `0100` = 256, `021` = 33, `04c00` = 19456.
  Есть также явные основания `xB`/`xD`/`xH`/`xO`/`xQ` и множитель `K`.
- Типизированная память `B/W/D/Q/T`, операторы `BIT`/`BY`, неявное сложение в адресных выражениях,
  `THIS`, переопределяемый `EQU`, пустые объявления данных и `DUP` без скобок.
- Повторные локальные метки вроде `L1`, ссылки вперёд `>L1`, области локальных меток в вызовах макросов.
- Позиционные макросы с завершением `#EM`, параметры `#1`…`#9`, `#L`, `#N`, `#S`, `#V`, числовые циклы
  `#R`/`#Q` и условия `##IF`/`##ELSE`/`##ENDIF`; include наследует диалект. У раскрытия есть лимиты и отмена:
  каждая граница цикла (и начальное значение обратного отсчёта `#Q`) — не больше 65536.
- Типизированные наложения `STRUC`, в том числе с заданной базой: поля описывают память без её выделения.
  В отладчике абсолютные типизированные поля используют текущий DS, доступны исходные имена локальных меток.
- Сокращения A86: `ENTER`, унарный `TEST`, трёхоперандный `MOV`, повторные `PUSH/POP/INC/DEC`, строковые
  команды со счётчиком и загрузка сегментных регистров. `BOUND` использует существующую поддержку 80186.
- Операнды стека FPU `0`…`7`, встроенные вещественные константы и арифметика констант в точности x87.
- По умолчанию плоская программа — COM; `ORG 0` выбирает BIN.

## Ограничения совместимости

Регистры A386, префиксы размера адреса/операнда и 32-битные команды требуют процессора 386, которого
эмулятор не реализует. Сам по себе реальный режим не делает такие программы совместимыми с 8086.
Компоновка объектных файлов, посимвольные макроциклы и часть редких расширений A86 не реализованы.
Соответствие оригинальному ассемблеру A86 байт в байт не заявляется.

Из 161 проверенного листинга книги автоматическая сборка выросла с 20 до 117 (95/128 отдельных файлов
и 22/33 извлечённых упражнений). Сборка или завершение процесса не доказывают правильность результата:
встречаются фрагменты, данные, ожидания ввода/IRQ и намеренно ошибочные задания.
Результаты проверки и команды повторного прогона — `reports/a86-dialect-2026-11-15.txt`.

Для разработчиков: `cargo test -p rustemu-asm --test a86_dialect` и
`python3 scripts/check_book_corpus.py <папка-arch> --out <новая-папка-отчёта>`.
