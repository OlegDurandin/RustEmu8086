# Учебный MVP на основе remu

Pilot Readiness V1 extends the original four-task MVP to 12 tasks (6 per ISA), without a schema change. See [the current catalog](../reports/pilot-readiness/learning-catalog.md) and [pilot status](../reports/pilot-readiness/GO-NO-GO.md). The four-task description below records the original MVP.

Этап 3 от 17 ноября 2026 года. Встроены ровно четыре открытых офлайн-задания. Сервер, аккаунт и LLM не используются. Ядра 8086 и MIPS32 не переписывались.

## Пользовательский сценарий

1. Открыть Examples → Learn и выбрать задание. Работает в desktop и tablet; перед заменой несохранённой программы используется прежний guard.
2. Прочитать цель, исходные условия и Hint; стартовая программа открывается в обычном редакторе. Run, Step, Step Back, CPU, Memory и Visual Step остаются доступны.
3. Нажать «Проверить решение / Check solution». Сборка идёт в существующей фоновой задаче (native thread / WASM Worker), исполнение — в отдельных коротких срезах между кадрами.
4. Для каждого случая увидеть passed / failed, нарушенное условие, ожидаемое и фактическое значение. Step limit, Timed out, Input exhausted, Unsupported и Assembly failed не считаются успехом.
5. Return to code закрывает карточку без изменения исходника. Check solution открывает её повторно. Правка источника, include или настроек инвалидирует старые результаты и отменяет активную проверку.
6. Export project (.remu) / Share link переносят упражнение, текущий код и открытые случаи. Личный C:, живая машина, breakpoints и watch не переносятся.

## Совместимость формата

В Project v1 добавлено опциональное поле `exercise`, отсутствующее в сериализации обычного проекта. Внутри него собственный `version: 1`. Старые .remu v1 по-прежнему читаются; их отсутствие `exercise` не меняет запуск, экспорт и настройки MARS. Старые бинарники, запрещающие неизвестные поля, отклонят новый учебный проект: для упражнений нужен этот выпуск. Версия обычного проекта не повышалась; неизвестная версия упражнения отклоняется до изменения документа.

Схема типов: [exercise.rs](../crates/rustemu-build/src/exercise.rs). Исполнитель и UI: [learning.rs](../crates/rustemu-ui/src/learning.rs).

```json
{
  "exercise": {
    "version": 1,
    "id": "8086-carry",
    "title": "8086 Carry across AL and AH",
    "description": "Цель и проверяемые условия",
    "architecture": "8086",
    "starter_code": "org 100h\nhlt\n",
    "step_limit": 10000,
    "time_limit_ms": 1000,
    "hint": "ADD меняет CF, ADC учитывает перенос",
    "cases": [{
      "name": "carry", "input": "", "initial_registers": {"AX": 255},
      "expected": {
        "output": null, "registers": {"AX": 256, "CF": 0},
        "memory": [], "termination": "Halted"
      }
    }]
  }
}
```

Окончание через DOS/MIPS exit записывается как `"termination": {"Exited": 0}`. Условия объединяются логическим И. `output` проверяет точное совпадение с нормализацией CRLF в LF. Регистры/флаги задаются именами, не произвольными выражениями. `memory` — список `{address, bytes}` с физическими адресами. Отсутствие условия не означает, что оно проверено.

## Ограничения ресурсов и изоляция

- Прежние ограничения .remu: 1024 файла, 4 МиБ исходников, JSON до 32 МиБ; без host fallback. Метаданные задания дополнительно ограничены: 16 случаев, 64 ожидаемых регистра, 32 начальных регистра, суммарно 256 байт memory assertions на случай, 4096 байт входа/ожидаемого вывода, 64 КиБ starter_code. Конкретные пределы title/id/description/hint проверяются до исполнения.
- От 1 до 200000 диспетчеризаций инструкции и от 1 до 5000 мс на случай. Фоновая сборка отменяется watchdog через 10 секунд. В UI один срез выполняет не более 1024 шагов либо 4 мс до следующей проверки; граница времени кооперативная, одна инструкция/системный сервис может занять дольше среза. Лимит времени случая считает только время внутри срезов (`CheckRun::advance`): паузы между кадрами — медленное устройство, скрытая вкладка браузера — не расходуют его, поэтому правильное решение не получает ложный Timed out. Это не замер задержки Stop.
- Для каждого случая создаётся новый Session с пустым временным диском, собственным вводом и без истории. Исходник и открытая отладочная сессия не заимствуются; личный диск не синхронизируется. 8086 IRQ выключен, время привязано к числу инструкций. Настройки MARS из проекта сохраняются, режимы delay slot не смешиваются.
- MVP разрешает консольный ввод/вывод и выход. Внешние устройства, MMIO, файловые операции, часы, RNG и диалоговые syscall не имеют сценария внешних событий и выдают Unsupported. Доступ к host-файлам запрещён независимо от диагностики. Превышение лимита вывода останавливает случай.
- Все случаи публичны и локально редактируемы; скрытых секретных тестов нет. Это средство самопроверки, не защищённая экзаменационная система. Нельзя считать passed доказательством решения всех возможных входов: проверены только объявленные случаи.

## Четыре задания

| Файл | Цель и условия | Проверки | Эталон и неверный вариант |
|---|---|---|---|
| [8086-carry.remu](../examples/learn/8086-carry.remu) | Прибавить 1 к AL и перенести CF в AH, закончить HLT | Три случая AX, AL/AH, CF/ZF | ADD AL,1 / ADC AH,0 проходит; один HLT нарушает Register |
| [8086-stack.remu](../examples/learn/8086-stack.remu) | Обменять BX/CX через стек, восстановить SP | Два случая BX/CX/SP и слова стека | Две PUSH и две POP проходят; один HLT нарушает Register и память |
| [mips-sum.remu](../examples/learn/mips-sum.remu) | Прочитать два целых, сумма по модулю 2^32 в $t0 | Положительные, отрицательные и overflow, завершение | Два syscall 5 и ADDU проходят; немедленный exit нарушает Register |
| [mips-max.remu](../examples/learn/mips-max.remu) | Знаковый максимум четырёх слов, не менять массив | $t0, байты массива, exit | Цикл с LW и сравнением проходит; немедленный exit нарушает Register |

Эталоны находятся в tests/learning-solutions и не включены в распространяемые учебные пакеты. Подсказки и описание целей находятся внутри каждого .remu.

## Проверки и доказательства

```sh
cargo test --offline -p rustemu-ui --test learning
cargo test --offline -p rustemu-desktop --lib learning_card
cargo test --offline -p rustemu-tablet --lib learning_card
cargo check --offline --target wasm32-unknown-unknown -p rustemu-web
```

Интеграционные тесты проверяют четыре эталона и четыре неверных решения, round-trip обычного v1 и упражнений, лимиты, неподдержанные сервисы, отдельные ошибки output/memory и сохранение открытой машины, исходника и personal.txt. Frontend-сцены проверяют реальную кнопку карточки, результаты и возврат к коду. Итоговые числа, команды и наличие PNG: [общий отчёт](../reports/top3-final-2026-11-17.md).
