# Проверка PILOT-READINESS V1 на реальном iPad

Проверяется кандидат для ручной валидации. Публикация сама по себе не означает готовность к внешнему пилоту. Автоматические тесты и desktop GUI не заменяют Safari, touch, IME и Files на физическом устройстве.

Основной адрес: https://olegdurandin.github.io/RustEmu8086/?ui=tablet

Перед проверкой откройте [маркер сборки](https://olegdurandin.github.io/RustEmu8086/build-info.json) и сохраните `commit`. Запишите модель iPad, версию iPadOS, дату, ориентацию и наличие внешней клавиатуры. Проверяйте обычный Safari; существующую работу предварительно экспортируйте в `.remu`. Для отдельной проверки импорта можно использовать приватную вкладку; её хранилище временное.

## Основной прогон — около 20–30 минут

Для каждой строки отмечайте PASS/FAIL и фактический результат. Непроверенное отмечайте NOT RUN.

| № | Что сделать | Ожидаемый результат |
|---|---|---|
| 1 | Открыть адрес в Safari. Examples → Hello, world (.com). Run | Приложение загружается, сборка завершается, появляется `Hello, World!`, программа заканчивается с exit code 0. Цель первого запуска — до 2 минут без помощи |
| 2 | Reload программы; выполнить Step, ещё Step, Step back; поставить breakpoint на исполняемой строке и Run | Next/Last и подсветка понятны; регистры меняются, откат возвращает предыдущее состояние; breakpoint останавливает перед инструкцией. Reload программы и перезагрузка страницы — разные действия |
| 3 | В контексте 8086 создать новый исходник из примера ниже и Run; после ожидания нажать Enter a key и ввести `A` | Появляется Waiting for input; без Reset программа продолжает выполнение, печатает `A`, BL=41h, выход 0. В редактор символ не попадает |
| 4 | Examples → MIPS32 examples → пример `sum.s`. Run; в Run I/O ввести `5` и отправить Enter/Send | До ввода есть Waiting for input; после ввода показано `sum = 15`, выход 0. Повторить отправку с системной и, если есть, внешней клавиатуры |
| 5 | Добавить разные комментарии в программы 8086 и MIPS32. Несколько раз переключить ISA | В каждом workspace сохраняется собственный текст; комментарии не пропадают и не смешиваются. Обычный ASM может помнить архитектуру файла; для однозначного переноса используйте `.remu` |
| 6 | В новом 8086-исходнике ввести `mov ax,not_a_defined_symbol`, собрать; исправить и собрать снова | Видно сообщение с проблемной строкой; приложение остаётся доступным, исправный код запускается; ошибочный исходник не запускает предыдущий образ |
| 7 | Examples → Learn: проверить, что есть по 6 задач 8086 и MIPS32. Открыть `8086 Carry across AL and AH` | Цель, Hint, Public test cases, Check solution и Edit code доступны; системная клавиатура не лишает возможности вернуться в редактор |
| 8 | В Carry нажать Check на исходном HLT; затем Edit code, вставить эталон ниже, снова Check; после успеха удалить ADC и проверить снова | Исходная и испорченная программы не проходят весь набор; эталон проходит три случая. После правки старый результат инвалидируется, новая проверка показывает конкретные expected/actual |
| 9 | В Learn открыть `MIPS ADDIU wrapping arithmetic`; Check исходного кода, затем эталона ниже | У исходного кода случаи 0 и 2147483647 failed, FFFFFFFF может корректно passed; у эталона все три passed |
| 10 | Share → export project: сохранить решённую задачу `.remu` в Files. Импортировать через Open/My programs в отдельной приватной вкладке, повторить Check | Safari действительно сохраняет файл, Files позволяет выбрать его; после импорта сохранены ISA, исходник, задача, публичные случаи и настройки; эталон снова проходит. Живое состояние CPU не переносится |
| 11 | Внести несохранённый комментарий; попытаться открыть другой пример, выбрать Cancel | Появляется предупреждение; после Cancel текст и признак изменений сохранены. После экспорта и обычной перезагрузки страницы отдельно проверить доступность сохранённого локального черновика |
| 12 | При несохранённом комментарии импортировать файл с содержимым `{"version":1,"files":` и расширением `.remu` | Появляется ошибка проекта; точный исходный текст и текущая задача не теряются. Не проверяйте на единственной копии важных исходников |
| 13 | В новом 8086-исходнике запустить бесконечный цикл ниже, нажать Stop. Затем в учебной задаче запустить проверку циклического решения и нажать Cancel check, если проверка ещё активна | Выполнение остановлено, UI остаётся доступным, исходник сохранён. Step limit/Timed out/Cancel не выдаются за passed. Если проверка завершилась до Cancel, отмена считается NOT RUN |
| 14 | Повторить редактирование/карточку/отладчик в портрете, альбоме и Split View; открыть Memory; прокрутить длинный код; сделать pinch zoom и вернуть масштаб | Кнопки, вкладки, диагностика и ввод достижимы; прокрутка не застревает, касания попадают в нужные элементы. Проверить русскую раскладку, выделение и многострочную вставку, скрытие/возврат системной клавиатуры |
| 15 | Share link: открыть ссылку в новой вкладке. Отдельно проверить большой проект и предложенный экспорт файла. По желанию добавить на экран Домой и повторить запуск/ввод/Files | Источник восстанавливается; большой проект можно передать файлом без потери кода. Результаты режима с экрана Домой отмечайте отдельно от обычного Safari |

### Клавиатурный пример 8086 (пункт 3)

```asm
org 100h
mov ah,0
int 16h
mov bl,al
mov ah,0Eh
int 10h
ret
```

### Эталон Carry (пункт 8)

Вставлять именно внутрь открытой задачи через Edit code — её публичные случаи и начальные регистры должны остаться.

```asm
org 100h
add al,1
adc ah,0
hlt
```

### Эталон MIPS ADDIU (пункт 9)

```asm
.text
main: addiu $t0,$t1,1
li $v0,10
syscall
```

### Бесконечный цикл 8086 (пункт 13)

```asm
org 100h
again: inc bx
jmp again
```

## Дополнительные проверки для координатора

- Проверить перенос многофайлового [8086-include.remu](../examples/projects/8086-include.remu): вывод `X!`; [mips-input.remu](../examples/projects/mips-input.remu): подготовленный ввод 40, результат 42. После экспорта/импорта include и подготовленный ввод должны сохраниться.
- На настоящем Safari через Web Inspector подтвердить исполнение assembler Worker на Assemble и Check. Один HTTP 200 или успешная загрузка WASM это не доказывает.
- Задержку Stop измерять отдельно: 10 повторов для простого цикла, REP MOVSW с CX=FFFF, интенсивного вывода, MMIO/robot и проверки циклического решения. Снимать высокочастотное видео/трассу от касания Stop/Cancel до кадра подтверждения. Сохранять сырые значения, median/p95/max; цель ≤100 мс пока не подтверждена. Обычный секундомер/длительность вызова автоматизатора не заменяют замер.
- Отдельно прогнать новые задачи уровня loop, memory и call, затем все 12 эталонов и неверных решений. Один passed означает только совпадение объявленных публичных условий.

## Как прислать результат

```text
Устройство / iPadOS / клавиатура:
commit из build-info.json:
Режим: Safari / экран Домой, портрет / альбом / Split View
Пункт чеклиста:
PASS / FAIL / NOT RUN:
Шаги:
Ожидалось:
Получилось:
Скриншот или короткая запись экрана:
```

Потеря правок, ложный полный успех неверного решения или зависание без возможности продолжить — причина остановить пилот. Сначала сохранить/экспортировать код, затем зафиксировать шаги и build; не очищать данные Safari в качестве первого способа восстановления.
